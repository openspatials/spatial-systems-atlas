A map of the parts an open metaverse needs

Four planes and one overlay. Arranged by consequence rather than by number, so the chain reads top to bottom.

Your entry point mostly picks your topology. Your topology decides which engine parts you are allowed to swap. The parts you can swap are the only places a standard can do any work.

PLANE 4

Entry points

“I want to build a metaverse” means five different projects
RUNG 1 Whole hosted platform Editor, runtime, hosting, identity, moderation, payments and an audience, all supplied. You write content, not infrastructure. DAYS · NO PORTABILITY
RUNG 2 Hosted backend, own client You pick the engine and write the world. You rent multiplayer, matchmaking, storage and voice. WEEKS · CLIENT IS YOURS
RUNG 3 Engine only, self-hosted An engine plus your own servers. Control is near complete, bounded by the welded parts below. MONTHS · ENGINE-BOUND
RUNG 4 Renderer plus libraries No engine. A renderer, an avatar system, a scene loader, physics and networking, assembled by you. Every socket is a real socket. MONTHS · FULLY PORTABLE
RUNG 5 Bare protocol node You implement addressing, handoff and state, and run a node. Not a world — a place other worlds can reach. RESEARCH PROGRAMME
PLANE 1

Topology

Where the computing happens, and who holds the authoritative world
MODEL A1 Cloud-rendered video The server rasterizes and streams finished frames. The client decodes video and sends input. It never sees geometry or an asset.
Wire
Video down, input up
Truth
Server, entirely
Cost
A graphics processor per user, per minute
Fails
Picture freezes; no local world
MODEL A2 Streamed geometry The server sends scene geometry on demand. The client rasterizes it but holds nothing in advance — no install, no asset library.
Wire
Geometry and scene data, streamed
Truth
Server, but drawing is local
Cost
Bandwidth and server-side scene assembly
Fails
Scene stops filling in; what arrived still draws
MODEL B Engine client, server state The client already holds the assets and draws locally. The server holds authoritative state and sends what changed. Ordinary multiplayer.
Wire
Small state deltas, sent often
Truth
Server for anything contestable
Cost
Asset delivery and simulation load
Fails
World draws, stops updating
MODEL C Distributed nodes, edge mesh Many small servers run by different people. Each holds truth about its own part. Shared regions need an agreement mechanism.
Wire
Peer state plus gossip or replication
Truth
Split; no single copy
Cost
Cheap per node, paid by its operator
Fails
Partially — local keeps working
Adaptive rendering — the shape that spans them   The server decides per client whether to rasterize or hand the geometry over, based on what the device can take, and falls back to server-side rendering when it cannot. A headset draws what must be low-latency while a nearby machine draws the rest. Treat this as a scheduling decision made at connection time, not a fifth model — but note that it makes A1, A2 and B runtime alternatives for the same session, not a choice made once at build time.
The honest picture   No production system is purely one model. Model B streams a heavy region as video from A1. Federated worlds are B servers with a C problem between them. A decentralized design usually re-centralizes at the directory that answers “where is that place.” Split rendering — headset draws the urgent, a nearby machine draws the rest — is a shape of its own. A system can be centralized on identity, federated on discovery, and peer-to-peer on state, all at once.
PLANE 2

Engine anatomy

Twelve parts in a shared harness — five of them welded shut
RendererTurns the scene into pixels via the device graphics interface.Replaceable in principle
Scene graphThe tree of objects and transforms. The engine's idea of what exists. Three ratified standards define one natively; the major engines use their own.Welded in the engines
Asset pipelineImport, convert, compress and package models, textures and animation.Replaceable
PhysicsCollision and anything that moves by rule rather than by script.Swappable, results differ
Game logic & scriptingThe rules of the world. What happens when you pick something up.Welded
Networking & replicationWhat is shared, who owns it, how often, how disagreements resolve.Welded
AudioPositioned sound, room response, occlusion, voice.Replaceable
Input & deviceControllers, hands, eyes, head pose, and the headset session.Replaceable
User interfaceMenus, panels and text over the three-dimensional world.Welded
PersistenceWhat survives a restart. Inventory, world edits, progress.Replaceable
PackagingTurning the project into something a user can run, and delivering it.Store-constrained
Editor & authoringWhere humans build. The real reason teams stay with an engine.Welded
Why this matters   A body can publish a perfect specification for any of the seven replaceable parts and still not move the market, because the five that bind you are untouched.
PLANE 3

Sockets & standards

Turn the overlay on: everything settled is a file, everything missing is a live session

Nouns — file standards

Something you can write down, hand over, and check offline.

Asset deliveryThe transfer format for 3D scenes. Genuinely settled.Covered
Scene compositionCore published 2025-12-12 — but it excludes geometry, materials and physics, and none of those is published.Contested
Graphics interfaceShips by default in all three browser engines.Covered
Immersive deviceNative access is multi-vendor. Browser access is not.Contested
Avatar descriptionAn international avatar exchange format is one stage from publication.Contested
Geospatial anchoringPose on Earth approved 2022, published 2023. Two tiled formats compete.Contested
Asset licence metadataA ratified extension attaches licence and attribution to the common asset format; the open avatar format carries it natively. Runtime support is partial.Covered
Rights enforcementPermissions still do not travel with the asset. Nothing in our coverage database reaches this natively or by extension.Empty

Verbs — session standards

Two running systems agreeing about a moving world, in real time. “Empty” means nothing ratified to build against today — not that nobody is working on it, and not that nobody does it.

AddressingNo ratified standard from an accredited body names a place and resolves it; a landscape report assessing 912 standards found none. Four projects and platforms do it natively in our database.Empty
Portal handoffTraversal is ratified; no ratified standard carries your state across the jump. A draft occupies this cell, and one recorded crossing carried pose, session, equipment and fifteen manifest facets between two world servers.Empty
Federated presenceNo way to know who is where, across operators.Empty
Identity & credentialsThe data model is ratified. The exchange protocol is not.Contested
Portable capabilityRatified credential formats carry claims about a holder, not permissions a world can act on. One draft is the only native occupant of this cell — version 0.4, from a co-chair’s own company. Say that before relying on it.Empty
State replicationWelded to each engine in practice. But one ratified standard defines networked state sharing across host computers — the only ratified standard on this map that does — an adoption gap, not a capability gap.Empty
Behaviour portabilityA skeleton moves between worlds. How it moves does not — in the engines. One ratified standard defines behaviour natively in our database; today’s formats pass it over.Empty
PhysicsThe same clause runs from the 2008 edition to the current fourth edition, December 2023 — in a format today’s engines ignore.Contested
Spatial audioAn international standard published 2025-11-03.Contested
The pattern   This plane scores one question: is there a ratified standard to build against. Our coverage database scores a different one — does this subject do this — and prints the same word “empty”. Take coverage claims from the database, not from this board. And a warning about the word empty: six times now a cell we called empty turned out to have been filled years earlier by a ratified standard the industry passed over — spatial audio, physics, avatar migration, humanoid skeletons, tiled terrain streaming, and shared state between running instances. So the problem is not capability, it is adoption, and writing another specification does nothing for an adoption gap. Before this group declares a gap, check whether the older standard already answered it and was passed over.
